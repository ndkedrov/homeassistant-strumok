# СтрумОК для Home Assistant

Custom component для [Home Assistant](https://www.home-assistant.io/), який
опитує локальний HTTP API вашої зарядної станції СтрумОК (`GET /api`, той
самий, за яким відкривається веб-панель плати) і показує її стан як пристрій
у Home Assistant: заряд авто, показники домашньої сонячної станції (генерація,
батарея, мережа, споживання), стан Wi-Fi і шини інвертора.

**Це read-only інтеграція.** Вона лише показує показники — керування зарядкою
(старт/стоп, зміна ліміту струму) через неї недоступне, бо локальний `/api`
плати наразі не має жодного ендпоінту для запису. Керувати зарядкою можна
через застосунок СтрумОК або хмарний Home Assistant-міст (`ha_client`
у прошивці) — це окремий, протилежний напрямок інтеграції.

Якщо вам потрібне саме керування або ви користуєтесь Home Assistant через
MQTT — дивіться паралельний шлях: MQTT Discovery, який плата підтримує
нативно (прошивка публікує сенсори сама, без цього пакета). Ця інтеграція —
альтернативний шлях для тих, хто не піднімає MQTT-брокер удома.

## Що ви побачите в Home Assistant

Один пристрій `СтрумОК` з такими entity (усі — сенсори, без керування):

| Що показує | Тип | Примітки |
|---|---|---|
| Стан заряду | сенсор (текст) | сирий ключ з плати, перелік значень ще не звірено на 100% живих плат |
| Струм заряду | сенсор, А | |
| Потужність заряду | сенсор, кВт | ⚠️ одиниця виміру — найбільш імовірне припущення, не підтверджений факт (див. розділ нижче) |
| Заряд домашньої батареї | сенсор, % | SoC інвертора/домашньої батареї, **не** батареї авто |
| Потужність сонячних панелей | сенсор, Вт | |
| Потужність батареї | сенсор, Вт | знак (заряд/розряд) не звірено емпірично |
| Потужність мережі | сенсор, Вт | |
| Потужність споживання | сенсор, Вт | |
| Заряд дозволено | бінарний сенсор | |
| Авто підключене | бінарний сенсор | на одноблочних платах часто `unavailable` — див. нижче |
| Wi-Fi онлайн | бінарний сенсор, діагностика | |
| Рівень сигналу Wi-Fi | сенсор, dBm, діагностика (вимкнено за замовчуванням) | |
| Шина інвертора підключена | бінарний сенсор, діагностика | |
| Час роботи | сенсор, діагностика | |
| Версія прошивки | сенсор, діагностика | |

Деякі показники (передусім усе, що йде з блоку `live.*`, тобто генерація/
батарея/мережа/споживання) залежать від того, чи плата взагалі впізнала карту
регістрів вашого інвертора. Якщо ні — відповідні сенсори будуть
`unavailable`, а не показувати нуль чи помилку. Це нормально й очікувано, не
збій цього пакета.

## Встановлення через HACS (як custom repository)

Цей пакет поки НЕ в офіційному каталозі HACS — додайте його як custom
repository:

1. Home Assistant → **HACS** → три крапки вгорі праворуч → **Custom
   repositories**.
2. У полі **Repository** вкажіть URL репозиторію (папку
   `integrations/homeassistant-strumok` цього репозиторію
   `strumok`, або окремий GitHub-репозиторій, якщо власник згодом винесе цей
   пакет туди окремо — уточнюйте актуальне посилання).
3. У полі **Type** оберіть **Integration**.
4. Натисніть **Add**.
5. У списку HACS знайдіть **СтрумОК**, відкрийте й натисніть **Download**.
6. Перезапустіть Home Assistant (**Settings → System → Restart**).

### Без HACS (вручну)

Скопіюйте теку `custom_components/strumok/` з цього репозиторію в
`<конфіг Home Assistant>/custom_components/strumok/` (поруч зі своєю
`configuration.yaml`) і перезапустіть Home Assistant.

## Налаштування

1. **Settings → Devices & Services → Add Integration**.
2. Знайдіть **СтрумОК**.
3. Введіть локальну IP-адресу або хост плати у вашій мережі — ту саму, за
   якою у вас відкривається веб-панель плати в браузері (наприклад
   `192.168.1.42`). Порт і пароль вводити не треба: локальний API плати
   працює на порту 80 і не вимагає автентифікації.
4. Натисніть **Submit**. Якщо плата відповіла — інтеграція одразу створить
   пристрій і всі доступні на цій платі сенсори.

Порада: якщо адреса плати в майбутньому зміниться (DHCP), найпростіше —
закріпити за платою статичну IP-адресу на вашому роутері, або видалити й
додати інтеграцію заново з новою адресою.

## Чому "Потужність заряду" позначено як припущення

Поле `evse.kw` у відповіді плати не має одиниці виміру, задокументованої в
коді прошивки. Назва натякає на кіловати, і саме так ця інтеграція показує
значення (`device_class: power`, `kW`) — але це найбільш імовірне
припущення за назвою поля й типовими величинами побутової зарядки, а не
перевірений факт. Якщо на вашій платі це число виглядає неправильно
(наприклад, завжди 0 при активному заряді, або порядок величини не сходиться
зі струмом × напругою) — це саме та розбіжність, яку контракт проєкту просить
звірити емпірично; повідомте про спостереження автору проєкту.

## Розробка та тести

```bash
cd integrations/homeassistant-strumok
python3 -m venv .venv && source .venv/bin/activate
pip install -r requirements_test.txt
pytest -q
```

Тести (`tests/test_parser.py`) перевіряють розбір відповіді `/api` —
зокрема те, що відсутність будь-якого поля (наприклад немає всього блоку
`live`, немає `evse.units`, чи немає окремого ключа `car`) ніколи не кидає
виняток, а лише робить відповідний сенсор `unavailable`. Тести навмисно не
вимагають встановленого пакета `homeassistant` — вони перевіряють чисту
логіку розбору (`custom_components/strumok/parser.py`), а не саму
інтеграцію в рантаймі Home Assistant.
